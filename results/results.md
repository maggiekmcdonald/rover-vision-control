# Simulation results

Generated by `demo/run_simulation.py`, which runs the full closed loop
(synthetic camera frame -> `ColorObjectTracker` -> `Navigator` dual-PID ->
`SimulatedDriver` bicycle-model kinematics) for 700 ticks at `dt = 0.05s`
(35 simulated seconds).

## Scenario

- The target wanders through world space along a Lissajous-style path
  (`x(t)`, `y(t)` each independent sine waves), giving it both lateral
  wander and depth changes relative to the rover.
- The rover starts offset from the target's initial position, with zero
  initial velocity and heading.
- At each tick, the target's true world position is converted into a
  bearing and range relative to the rover's *current* pose, then projected
  into a synthetic 640x480 BGR frame (a colored circle on a noisy gray
  background) exactly like a real camera would see it.
- The real `ColorObjectTracker` (HSV threshold + contour + minimum
  enclosing circle) detects the target in that frame with no shortcuts --
  the same detector used for a live webcam feed.
- The `Navigator` runs two independent PID loops (steering off centroid
  x-error, speed off apparent-radius error vs. an ideal following distance)
  to produce steering/speed commands.
- `SimulatedDriver` integrates those commands through a bicycle kinematic
  model to update the rover's world pose.

## Result

`path_tracking.png` plots the target's ground-truth world path (red, solid)
against the rover's driven path (blue, dashed). The rover starts well
outside the target's loop, closes the distance over the first several
seconds, and settles into pursuing the target's motion -- visible as the
rover's path curving to track the general shape of the target's loop rather
than moving in a straight line or standing still.

- Final target-rover separation: **0.91 m**
- Mean target-rover separation over the run: **1.02 m**

`tracking_demo.gif` is a downsampled animation of the actual synthetic
camera frames fed into the tracker during this run (every 10th frame,
resized and palette-reduced to keep the file small), showing the target
blob moving through the frame as the closed loop runs.

## Reading the numbers

The steady nonzero separation is expected and by design: the navigator
targets a fixed "ideal following distance" (calibrated to an apparent
target radius of 60px), not zero distance -- a real rover that tailgates
its target that closely would run into it. The relevant signal is that the
separation stabilizes and tracks the target's motion rather than growing
without bound, which is what a converged dual-PID follower should do.
